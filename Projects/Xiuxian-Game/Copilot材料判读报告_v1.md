## 2. 冲突项（H1–H8）

> 冲突判定口径：① 与《10 定稿》《05 人物卡规范》或 `xiuxian_working_v1.5` 明文规则相抵；② 两处规则并存会导致校验器无法判定；③ 同一语义存在两套不兼容定义。

### H1｜正史层字段没有落点，Schema 必须改版本才能接〔严重性：高〕

- **Copilot 主张**：新增 `canonTrack` / `canonAnchor` / `timelinePhase` / `playerIntervention` / `observationMode`（`Copilot的回应.md:341-347`），并自承"具体名称可以调整，但语义必须先定下来"（`:349`）。
- **冲突出处**：《10 定稿》节点字段全表 `:261-295` 无这五个字段；`:355` 校验规则第 1 条「Schema 字段与类型校验；**未知字段报错**」。
- **冲突实质**：这不是补字段，是 **Schema v2 ＋ 校验器 ＋ 正史数据源** 三处联动。更硬的一处：《10 定稿》`:360` 规定「同一 tick 多个 `main` 命中 = 校验错误」，一旦引入"正史锚点事件"，它与普通 `main` 事件的优先级关系必须先定，否则事件一多就成批互撞，而且报错点在运行期而非加载期。
- **附带事实纠正**：Copilot 全篇以 `data/events/` 为既成目录（`:252` `:727`），但该目录**在仓库与本机都不存在**。GitHub trees API 实查 `Projects/Xiuxian-Game/可运行测试第一版/data/` 只有 `items/ npcs/ starters/ text/ state-template.json tuning.json world.json`；Copilot 原文"`data/events/` 为空"是事实错误——**不是空，是没有**。
- **建议**：见 R1。

### H2｜Effect 失败语义：两份文件加起来仍无事务边界〔严重性：高〕

- **《10 定稿》**：`:93-95`「`currencyBalances` / `inventory` 禁止钳制，**越界即报错并中止该 Effect**」。
- **Copilot**：`:461`「失败时**整体回滚**」。
- **冲突实质**：两句话不兼容，而且都太粗。一个 `onSuccess` 通常挂 3–5 条 effect，第 3 条越界时——前 2 条留不留？`ledger` 写不写？半个存档怎么办？《10 定稿》冻结了"单条中止"，Copilot 提出"整组回滚"，但**两者都没定义边界在哪一层**。这是 M1 一接事件就会出现的"半写存档"，且是最难复现的一类 bug。
- **建议**：见 R2。

### H3｜`understanding.level` 出现第二套枚举，且新增"误解"态〔严重性：中〕

- **《10 定稿》**：`:56` 字段 `understanding: [{topicId, level, evidence}]`；`:64` 取值域 `未接触 → 初识 → 入门 → 熟练 → 精通 → 自成体系`（明文承 `12_GM` §1）；条件操作符 `understandingLevel` 见 `:324`。
- **Copilot**：`:186-192` 用 `unknown / heard / understood / confirmed / misunderstood`，并在 `:194` 自述"具体枚举必须以你的正式规则为准"。
- **冲突实质**：同一字段两套枚举，validator 无从判定。
- **但有一条值得留**：`misunderstood`（**知道，但知道错了**）是六阶**装不下**的语义。六阶是"知道多少"的递进，而 `01_GM_True_History` 的历史矛盾五来源里，「抄写误差」「势力删改」正需要"记错"这个态。若一律用 flag 表达，等于把主角职业的核心风险（他抄的东西是错的）挤到系统外。
- **建议**：见 R3。

### H4｜测试节点 `test.pipeline.01` 会被自家校验器拦下〔严重性：中〕

- **Copilot 主张**：阶段 1 先写"无剧情价值"的夹具节点 `test.pipeline.01`（`:364-389`），阶段 4 扩成 `test.pipeline.01→02→03` 最小闭环（`:476-486`），落位为 `data/events/` 下的事件文件。
- **冲突出处**：《10 定稿》`:262` id 命名只允许 `main.ch<NN>.<NN>` / `side.ch<NN>.<NN>` / `ambient.<regionSlug>.<NN>`；`:263` `kind` 只有 `main|side|ambient`；`:356` 校验第 2 条「id 全局唯一；**命名规范校验**」；`:294` `defaultOutcome` 必填；`:359` 软锁检测；`:354` 校验项含 `region`/`location` 必须存在于 `world.json`。
- **冲突实质**：夹具要么被自己的校验器拒收，要么被"豁免"后长期污染正史内容目录——两条路都会让"校验器是可信门槛"这件事作废。
- **建议**：见 R4。

### H5｜`data/events/` 目录契约在《10 定稿》里是空白，Copilot 当成了既成事实〔严重性：中〕

- **Copilot**：`:252` `:727` 以 `data/events/*.json → build-data.js → 事件索引` 为主干路径。
- **《10 定稿》**：只规定长文本走 `data/text/*.json`（`:301`），**从未规定事件文件目录、分卷方式、加载顺序、单文件多事件还是单文件单事件**。
- **冲突实质**：不是直接冲突，是**契约空白被单方面填了**。这类空白由外部材料先填，后续所有文档就会把它当既定事实引用。
- **建议**：见 R5。

### H6｜把已经裁定过的事重新列为"待回答"〔严重性：低，但会污染文档〕

- **Copilot**：`:355` 第 3 问「玩家不在场时是否继续推进」；`:733` 第 7 项同义。
- **事实**：YY 已裁定「世界自走要真做」（玩家不介入也推进）。
- **冲突实质**：不算规则冲突，但它是**信息滞后**。若原样抄进规范，后续每一份文档都会再抄一遍这个"未定项"，让已定论看起来悬空。
- **建议**：任何转抄此材料时，此问一律标注「已裁定，见 2026-10-16 裁定记录」，不得作为待决项。

### H7｜技术断言无据，不得升格为容量承诺〔严重性：低〕

- **Copilot**：`:605`「几百个结构化事件节点通常不会首先撞上浏览器极限」。
- **反证条件**：`scripts/build-data.js` 把数据整体打包进 `data-bundle.js` 启动即全量加载；本地实测 `data-bundle.js` 仅 15,939 字节。该样本**不能**外推到几百节点。
- **建议**：保留为假设；若要变成承诺，先让 Antigravity 造 200 个合成节点实测加载时间与内存，出数据再谈。

### H8｜双轨 `statePatch` / `effects` 与「唯一权威」有张力〔严重性：中〕

- **Copilot**：`:463-470` 建议两套并存，理由是"二者最终都经过同一个状态校验器和 ledger 层"。
- **冲突出处**：《13 进度条离散化与N7唯一权威闭环回执_v1.md》已闭环「唯一权威」；《10 定稿》`:351` 规定 effect 后必须写 ledger。
- **冲突实质**：两套写入口并存，"唯一权威"名义上还在、实际已分叉。AI 调试路径一旦能改与正史结算同名的字段，存档就不再可复现。
- **建议**：若保留，必须补三条硬规则：① `statePatch` 不参与正史结算；② 不写正史 ledger（或写入独立调试 ledger 并在存档中标记来源）；③ 其产生的存档不得作为正史回归测试基线。否则应移出离线运行时，只留在开发工具里。

| **A** | 做成事件字段（`canon: {track, anchor, phase}` 写进 Event Node） | 改动小、一个文件表达完整；但 `main` 事件与锚点事件挤同一命名空间，`:360`「同 tick 多 main 命中即报错」需重写为"锚点优先"规则，且小说文本会长在事件数据里 |
| **B** | 独立 `data/canon/` 正史时间轴文件，事件只引用 `canonAnchorId` | 小说线／游戏线数据彻底分离，符合双轨；代价是新增一个数据源和一套交叉校验（锚点 id 必须在事件里被引用，且不可可达则报错） |
| **C** | 暂不做正史锚点，M1 只做玩家局部线 | 开工最快；但 A2 的 id 规范无从冻结，M2 接正史时小说侧的对齐工作会整体重做一次 |

**我的建议：B。** 理由：双轨是作品的形态前提，而 A 会让正史与玩家内容混在同一份数据里，将来小说改一行就得动事件文件。但这是你的世界观与作品结构决定的事，不是我该替你选的。

### R2 —— Effect 事务粒度定在哪一层？（对应 H2）

| 选项 | 语义 | 后果 |
|---|---|---|
| **A** | 单条 effect 原子：越界只丢这一条，其余照常执行 | 实现最简；但一个 choice 的奖励可能"给了一半"，玩家看到的状态会自相矛盾 |
| **B** | 整个 outcome 组原子：`onSuccess` / `onFail` 内任一条失败，整组回滚，ledger 不落 | 语义最干净、最容易回归测试；代价是编剧写错一个数字，整段结果静默不生效——**必须强制报错并在结果卡提示，不许静默回滚** |
| **C** | 整次事件结算原子：连同 `next` 跳转一起回滚 | 最安全；但事件与事件之间不可分割，世界自走的推进步长会变得很重 |

**我的建议：B ＋ 强制报错。**《10 定稿》`:93-95` 的"中止该 Effect"应改写为指整个 outcome 组，并把"A 条成功、第 B 条越界"列为**校验期错误**而不是运行期兜底。

### R3 —— `misunderstood`（误解）怎么落？（对应 H3）

| 选项 | 做法 | 后果 |
|---|---|---|
| **A** | 只用六阶，误解用 flag（如 `topic.cliff.clue.wrong`） | 不动 Schema；但"知道但知道错"无法参与 `understandingLevel` 门控，相关事件只能写成一堆 flag 特判 |
| **B** | 六阶之外增设 `误解` 作为**平行态**（不是第七阶，与六阶互斥但可共存于不同 topic） | 能表达主角职业的核心风险（他抄的是错的），且与"历史矛盾五来源"咬合；代价是 `understandingLevel` 判定要明确"误解态下如何比较" |
| **C** | 拒绝，按 A 处理 | 无代价，也无收益 |

**我的建议：B**，但必须同时写下判定语义：`误解` 不进六阶递进链，只允许由带 `evidence` 的 `understanding.set` 显式写入，且任何 `gte: 熟练` 的判定在误解态下**视为不满足**（不能拿错的认知当精通）。

### R4 —— 测试夹具放哪、要不要开 `test.` 白名单？（对应 H4）

| 选项 | 后果 |
|---|---|
| **A** | 夹具放 `tests/fixtures/`，不进 `data/` | 内容目录保持纯净，校验器不用开洞；代价是夹具跑的是另一条加载路径，验证不到"build-data 真实打包"这一段 |
| **B** | 夹具放 `data/events/_fixtures/`，validator 对 `test.` 前缀开**显式白名单并打印跳过条数** | 走真实打包路径；代价是白名单本身是漏洞面——一旦有人用 `test.` 前缀写正式事件，会被静默跳过 |

**我的建议：A ＋ 给 build-data 加一个 `--fixtures` 开关**：默认不带夹具，CI 时带上跑一遍打包路径。这样两边都要，也不留白名单。
