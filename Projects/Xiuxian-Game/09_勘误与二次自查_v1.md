## 2. 错误原因：我的抓取脚本用了增量方式

当时的脚本逻辑是「**只下载本地不存在的新文件**」：

| 文件 | 状态 | 结果 |
|---|---|---|
| `data/*.json`、`scripts/*`、`data-bundle.js` | 新文件 | ✅ 下载了（重构后版本） |
| `app.js`、`index.html` | 本地已存在 | ❌ **没有重新下载 → 我读到的是 10-15 23:38 的旧版本** |

**而且证据本身是自相矛盾的**：我手上明明已经有 `data-bundle.js` 与骨架化的 `data/world.json`（两者都是 M0 的产物），却同时得出「M0 未开始」的结论。**这个矛盾我没有察觉。**

**责任完全在我。** Antigravity 在《06 报告》里把原因解释为「抓取快照早于最新 push」——我当时接受了这个解释，**但没有回去验证它是否成立**。直到 YY 要求核对，我才用 commit 时间线查实：**不是"快照早于 push"这种时序误差，而是我的工具只做了增量下载。**

**这是冒失，不是误差。**

## 6. 本轮新增发现

### N5 · 引擎写 `inventory` 用 `id`，数据文件与标准用 `itemId`

| 位置 | 字段 |
|---|---|
| `v0.1-data-standard.md:95` | **`itemId`** |
| `data/starters/placeholder-starter.json` | **`itemId`** |
| `app.js` L727 / L782 / L883 `inv.push({...})` | **`id`** |
| `app.js` 全文 `itemId` 出现次数 | **0 次** |

**与 N2（currency）完全同一类：数据文件对、引擎运行时写出的形状不对。**

**要求**：`inv.push` 写入 `itemId`；读取与去重也统一按 `itemId`（目前 L725 / L780 / L881 是按 `item.name` 去重的，也应收紧）。

### N6 · 校验器对「条目级字段」完全没有防线

- `state-template.json` 的 `inventory` 是**空数组** → 必填反向检查看不到条目内部
- `validate-schema.js` 全文**不含** `itemId`，**不含** `quantity`
- 因此 **N2 与 N5 这两类「引擎写出非标准形状」的问题，校验器在结构上不可能抓到**

**要求**：校验器需支持**条目级 schema 校验**——对 `inventory[]`、`currencyBalances[]`、`relationships[]` 的元素定义必填字段与类型；并对**运行时存档**同样执行一遍（否则只能保证模板正确，保证不了真实存档正确）。
