# v0.1 数据标准

本文件是角色存档、单局配置、资源流水与网页脚本的数据口径。字段和单位以此为准；未定义的数值规则不得由实现自行补造。

## 1. 境界标准

境界顺序固定为：

1. 感气
2. 炼气一至九层
3. 筑基
4. 金丹
5. 元婴
6. 化神
7. 炼虚
8. 合体
9. 大乘
10. 渡劫

数据表达规则：

- 感气：`name="感气"`，`level=null`，`stage=null`。
- 炼气：`name="炼气"`，`level=1..9`，`stage=null`。
- 筑基及以上：`name` 为境界名，`level=null`；只有已确认具体阶段时填写 `stage`（初期 / 中期 / 后期 / 圆满），否则为 `null`。
- 不使用“仙境”作为渡劫之后的默认境界；新增境界须先修订本标准并确认。

例：`{"name":"炼气","level":3,"stage":null}`、`{"name":"筑基","level":null,"stage":"初期"}`。

境界只表示修行层次，不单独决定胜负。突破条件和修为进度不在本文件设定固定数值公式。

## 2. 角色状态 JSON

网页和存档统一使用 camelCase 字段。未知值用 `null` 或空数组，不用猜测值填充。

```json
{
  "schemaVersion": "0.1",
  "sessionId": "",
  "updatedAt": {
    "inGameDate": "YYYY-MM-DD",
    "timeOfDayMinutes": 0
  },
  "character": {
    "id": "",
    "name": "",
    "age": null,
    "background": "",
    "identity": "",
    "spiritualRoot": "",
    "constitution": "",
    "realm": {
      "name": "感气",
      "level": null,
      "stage": null
    },
    "cultivationProgress": null,
    "spiritualPower": {
      "value": null,
      "unit": null,
      "controlState": ""
    },
    "fatigue": {
      "value": null,
      "scaleId": null,
      "description": ""
    },
    "injuries": [],
    "inventory": [],
    "currencyBalances": [],
    "relationships": [],
    "reputation": null,
    "debts": [],
    "goals": [],
    "activeTasks": []
  },
  "gameWorld": {
    "continent": "",
    "location": "",
    "faction": ""
  },
  "world": {
    "currentLocationId": "",
    "events": []
  },
  "ledger": []
}
```

字段约定：

- `gameWorld`：当前本局已确认的世界范围，用于读取/展示和保存玩家确认的大陆、地点、势力。值统一为字符串名称，不写入未确认的设定。
- `world.currentLocationId`：运行时位置 ID，用于脚本和存档兼容。网页可保留该字段，作为位置信息的稳定键，不要强制将其替换成显示名。
- `cultivationProgress`：未定义全局单位，默认 `null`；启用数值前须在单局配置写明单位和量表。
- `spiritualPower`、`fatigue`、伤势：原规则没有统一数字范围。可用文字记录；若本局采用数值，必须带有经确认的 `unit` 或 `scaleId`。不将伤势与生命值混用为一个字段。
- `inventory` 条目使用 `{ "itemId": "", "name": "", "quantity": 1, "unit": "件", "condition": "", "ownerId": "" }`。数量按物品实际单位计；未定义重量、耐久或品质尺度前不推测。
- `currencyBalances` 条目使用 `{ "unit": "lowGradeSpiritStone", "amount": 0 }`。
- `relationships` 条目记录 NPC ID、关系描述及变化依据；关系没有统一数值分。
- `ledger` 记录每次状态变化的时间、行动/原因、字段、变化前、变化量、变化后及确定程度。流水是审计记录，当前状态是其核对后的结果。

## 3. 日期与时间推进

- 存档日期统一用公历 `YYYY-MM-DD`；游戏内时间与现实创建/更新时间分开保存。现实时间流逝不会自动推进游戏时间。
- `timeOfDayMinutes` 是当日已过分钟数，范围 `0–1439`；每经过 1440 分钟，日期加一天并将分钟数按余数归零。
- 固定换算：1刻约15分钟；4刻为1时辰；1时辰为120分钟；1日为12时辰（1440分钟）。
- 行动耗时按已确认规则或本局校准值记为分钟数。未校准的耗时须标记为估计/待确认；不得事后追加未告知的成本。
- 只有行动实际经过的时间推进日期。长行动期间应结算适用的资源消耗、伤势/疲劳、期限及世界/NPC行动；不得因时间经过而自动突破或完成目标。
- 节气、季节或修仙历称谓可作为显示文本，但不替代公历存档日期；其换算规则未配置前不自动推演。

## 4. 资源单位

| 资源 | 标准单位/记录方式 | 规则 |
|---|---|---|
| 时间 | 分钟（整数） | 时辰与刻按上节换算；时间流水不得重叠或重复结算。 |
| 低阶灵石 | 枚，`lowGradeSpiritStone` | 可与碎灵按固定账面比例换算。 |
| 碎灵 | 枚，`fragment` | 10枚碎灵 = 1枚低阶灵石。换算只用于记账，不代表所有交易都接受兑换。 |
| 铜钱 | 文/枚，以本局明确选定的名称记录 | 与灵石、碎灵没有固定兑换率；按地点和交易记录。 |
| 其他货币 | 独立 unit ID + 数量 | 不与现有货币自动换算。 |
| 物品/丹药/材料 | 数量 + 明确单位（件、份、枚等） | 按实际交易/消耗单位记录，不推算重量或价值。 |
| 修为进度、灵力、疲劳、伤势、神识负荷 | 文字状态；或本局确认的数值 + unit/scaleId | 项目没有全局数值单位、上限或阈值；不得默认使用 `health=100` 之类的隐含规则。 |
| 人情、名声、关系、债务 | 对象/内容/状态及因果记录 | 不折算成通用点数；债务若为货币债务，须注明币种、金额、期限与条件。 |

每笔交易应记录数量、单价、币种、总价、来源和去向；总价必须可复算。价格由地点、供需、品质、风险、关系与运输等因素决定，不设跨地区统一基准价。

## 5. 实现约束

1. 网页、AI 提示词、配置模板和存档都使用本文件的字段名与单位。
2. 不支持或未配置的值保持 `null` / 空数组，并在界面显示“未设定”，不能静默替换为0。
3. 新增字段、单位、境界或换算规则时，先更新本文件的版本，再同步其他文件和脚本。
4. 本标准统一数据表达，不改变行动判定、成长代价、世界观或玩家确认流程。
5. `gameWorld` 与 `world.currentLocationId` 可同时存在；`gameWorld` 侧重“当前已确认的世界概览”，`world.currentLocationId` 侧重运行时位置 ID。两者都应被保存和加载，避免旧存档失效。
