# 小说与游戏共享 ID 规范 v1

| 项目 | 内容 |
|---|---|
| **用途** | 让小说与游戏指向**同一个世界的同一个东西**：小说里写「某某药铺」，游戏事件数据里引用同一个 ID，两边永不脱钩 |
| **产出方** | 小肥（代决，依据 `Copilot的回应.md:543-588`，2026-10-16） |
| **适用范围** | 剧本线全部文档、小说正文、以及后续由剧本转换成的事件数据 |
| **状态** | 生效。本文件不含任何已定人名地名（那是 YY 的创作范围），只冻结**规则与登记方式** |

## 1. 一条规则，先记住这个就够

> **中文名是给人看的，ID 是给机器看的。一个东西只有一个 ID，登记之后不改。**

- 小说正文**只写中文名**（或称呼），不写 ID。
- 游戏事件数据**只写 ID**，不写中文名。
- 中文名可以改（改叫法、改绰号、改字号），**ID 不改**；真要改 ID，必须留一条映射记录，不许直接覆盖。
- 同一个实体在小说和游戏里叫法不同是允许的（例如全名／小名／外号），**ID 只有一个**。

## 2. ID 命名格式

小写英文 ＋ 短横线，只允许 `a-z 0-9 - .`。前缀标明类别：

| 类别 | 前缀 | 格式 | 示例（示例只为演示格式，**不是已定内容**） |
|---|---|---|---|
| 玩家角色 | `player` | `player.<slug>` | `player.main` |
| 小说主角 | `npc` | `npc.<slug>` | `npc.<slug>`（名字定了再登记） |
| 其他人物 | `npc` | `npc.<slug>` | 同上 |
| 地点 | `loc` | `loc.<slug>` | `loc.<slug>` |
| 地区 | `region` | `region.<slug>` | `region.<slug>` |
| 势力／组织 | `faction` | `faction.<slug>` | `faction.<slug>` |
| 话题／知识 | `topic` | `topic.<slug>` | `topic.<slug>` |
| 物品 | `item` | `item.<slug>` | 见 `data/items/items.json` |
| 技艺／功法 | `tech` | `tech.<slug>` | — |
| 正史锚点 | `novel` | `novel.ch<NN>.anchor.<slug>` | `novel.ch01.anchor.<slug>` |
| 游戏事件节点 | `main` / `side` / `ambient` | `main.ch<NN>.<NN>`、`side.ch<NN>.<NN>`、`ambient.<regionSlug>.<NN>` | 命名规范见《10 定稿》`:262` |

**注意**：事件节点与正史锚点的 ID 格式**已由《10 定稿》`:262` 与本次代决（正史锚点独立存放）确定**，不得自行另立格式。

## 4. 与设定集的关系（不得越界）

1. 本规范只解决**命名与对齐**，不产生任何世界观内容。
2. 已作废的占位名（`青冥洲`、`青云坊市`、`晨曦大陆`、`后山洞府`、`玄风宗`、`陆青云`、`采药老叟`）**不得登记**，不得作为正史引入。
3. 登记一个新地名时，若它与 `xiuxian_working_v1.5` 的既有地区设置（如唯一地点候选「临川镇」）冲突，先停下问 YY，不得自行择一。
