1. **关于 5.3 进度条**：

## 2. 5.3 进度条离散化改造详报（彻底消灭经验值刷条）

按照《12 报告》§3 的指导建议，我们彻底废弃了连续百分比进度条与平滑宽度过渡，全面重构为**离散 3 段阶梯式指示器**：

### 2.1 样式重构（`styles.css`）
- 彻底废除 `.progress-fill` 与 `transition: width 0.3s ease`；
- `.progress-track` 转为 Flex 容器：`display: flex; gap: 5px; width: 100%; height: 6px;`；
- 引入 `.progress-segment` 离散块（3 段）：
  ```css
  .progress-segment {
    flex: 1;
    height: 100%;
    background: rgba(255, 255, 255, 0.08);
    border-radius: 2px;
    border: 1px solid rgba(255, 255, 255, 0.05);
  }
  .progress-segment.active {
    background: linear-gradient(90deg, #2e7d32, #4caf50);
    box-shadow: 0 0 6px rgba(76, 175, 80, 0.35);
    border-color: rgba(76, 175, 80, 0.5);
  }
  .progress-track.ready .progress-segment.active {
    background: linear-gradient(90deg, #d4af37, #f7d88d);
    box-shadow: 0 0 8px rgba(247, 216, 141, 0.6);
    border-color: rgba(247, 216, 141, 0.8);
  }
  ```

### 2.2 逻辑驱动（`app.js`）
在 `renderState` 中：
- 彻底消灭任何 `style.width = ...%` 动态计算；
- 严格按 `character.realmStability` 与 `character.progressBand` 离散状态点亮分段：
  - `accumulating` + `initial`：点亮 **1 段**；
  - `accumulating` + `marked`：点亮 **2 段**；
  - `accumulating` + `near`：点亮 **3 段**；
  - `ready`（条件齐备）：**3 段全亮**并追加 `.ready` 金色光晕样式；
  - `consolidating`（突破待巩固）/ `unstable`：0 段点亮。

### 2.3 测试盲点补齐（`tests/no-percentage-ui.test.js`）
测试套件正式扩充至渲染路径与 CSS 检查（第 4 项测试）：
- 断言 `app.js` 中严禁出现 `fill.style.width`、`style.width = ...maxCultivation` 等动态宽度计算；
- 断言 `styles.css` 严禁出现 `transition: width`；
- 断言必须采用 `progress-segment` 离散结构。
- ✅ **全站去百分比与离散段位断言 100% 通过**。

## 3. N7 唯一权威闭环详报（消灭双源并存与读旧写新）

针对《12 报告》§5 提出的 N7 问题，我们采取了最彻底的 **方案 (a)：全量清除 `cultivationProgress`，确立 `progressInternal` 为唯一权威字段**。

### 3.1 权威收口与全量数据清除
1. **数据模板与开局文件**：
   - `data/state-template.json`：彻底删除 `cultivationProgress` 键，保留 `progressInternal: null`、`realmStability: "accumulating"`、`progressBand: "initial"`；
   - `data/starters/placeholder-starter.json`：彻底删除 `cultivationProgress` 键，保留 `progressInternal: 10`；
   - 全量重新打包 `data-bundle.js`，保证哈希一致（`sha256:0a334165...`）。
2. **静态校验器防护（`scripts/validate-schema.js`）**：
   - 在 `CHARACTER_REQUIRED_FIELDS` 必填清单中，彻底移除 `cultivationProgress`，**正式将 `progressInternal`、`realmStability`、`progressBand` 列入必填反向检查**；
   - 在禁止字段（Forbidden fields）中增加拦截：
     ```javascript
     if ('cultivationProgress' in character) {
       error(file, idPrefix, 'character.cultivationProgress', 'Forbidden legacy field "cultivationProgress" detected! Standard authority field is "progressInternal" per 10 baseline & N7.');
     }
     ```
   - 补充 `progressInternal`（非负数值或 null）、`realmStability`（5 大枚举值）及 `progressBand`（3 大枚举值或 null）的强类型校验。

### 3.2 引擎运行时彻底切断双源（`app.js`）
1. **白名单收口**：`CHARACTER_PATCH_FIELDS` 移除 `cultivationProgress`，仅保留 `progressInternal`；
2. **初始化收口**：`makeInitialState` 移除 `cultivationProgress`；
3. **读取唯一化**：
   - `formatCultivationStatus`：直接读取 `const curr = Number(char.progressInternal || 0)`，移除所有 fallback；
   - `generateLocalSimulation`：直接读取 `const currProgress = Number(char.progressInternal || 0)`；
4. **写入单源化**：
   - `cultivate`、`explore`、`combat`、`breakthrough` 所有行动在产生修为变动时，**仅向 `charPatch.progressInternal` 写入，彻底消除 `charPatch.cultivationProgress` 写入**；
5. **运行时存档双重阻断**：
   - `validateState` 与 `validatePatch` 同步将 `progressInternal` 纳入必填，并对传入 `cultivationProgress` 抛出强异常，杜绝任何旧字段流入。

### 3.3 专项自动化断言测试（`tests/progress-internal-authority.test.js`）
我们新建了专项测试套件，包含 4 组刚性断言：

- **测试 2**：扫描 `validate-schema.js`，断言新字段已被纳入必填且包含针对旧字段的拦截；
- **测试 3**：运行时构造包含 `cultivationProgress` 的对象，断言被 `validateState` 精准拦截；
- **测试 4**：静态扫描 `app.js`，断言没有任何向 `charPatch.cultivationProgress` 写入的代码，也没有任何读取旧字段的回退代码。
