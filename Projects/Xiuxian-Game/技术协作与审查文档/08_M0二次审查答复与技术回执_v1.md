## 3. 核心改进落地详报

### 3.1 叙事、数值与物品三权分立（R1 闭环）

按照策划与编剧的工作流分工，将代码中所有硬编码剥离至三个独立的数据层：

```
可运行测试第一版/data/
├── text/
│   └── narration.json      ← 编剧层（YY负责）：16段行动叙事、全部洞察文案、预设行动文本、建议流转
├── tuning.json             ← 策划数值层（小肥负责）：疲劳阈值与增量、物价、时间流速、数值区间、产出配置
└── items/
    └── items.json          ← 道具字典层：物品机器ID、名称、单位、分类、描述与基准物价
```

#### ① 编剧文案库 (`data/text/narration.json`)
收录全部 16 段行动叙事、全部洞察、行动默认输入文案与建议行动。支持标准插值占位符：
- `{location}`：当前福地/地点名称
- `{gain}`：修为增长数值（百分比）
- `{itemName}`：所采摘/获得的灵植名称
- `{found}`：探寻发现的灵石数量
- `{currencyName}`：货币显示名称（由 tuning 配置驱动）
- `{loot}`：战斗斩获材料名称
- `{nextLvl}`：晋级达到的境界层数
- `{currProgress}`：当前修为百分比
- `{cost}`：采买消耗货币数额
- `{pill}`：购置丹药名称
- `{reward}`：杂事结算灵石酬金

#### ② 策划数值库 (`data/tuning.json`)
代码中所有原先硬编码的数值常量均已收口：
- 疲劳上限与消耗：`fatigue.max = 100`（代码由读取 `TUNING.fatigue.max` 驱动，不再硬编码 `Math.min(100, ...)`）；`cultivate: 12`、`explore: 20`、`combat: 30`、`breakthrough_fail: 15`、`rest: 0`、`task: 25`、`trade: 6`、`social: 8`。
- 疲劳状态档位及描述：`thresholds` 与 `labels` 集中驱动，由 `getFatigueDescription()` 动态返回。
- 突破门槛与成长：`breakthroughEligibilityThreshold: 100`、`powerGainPerLevel: 15`。
- 坊市交易与物价：`buyItemId: "item.qi-pill"`、`buyCostCurrency: "lowGradeSpiritStone"`、`buyCostAmount: 6`。
- 掉落与结算：`herbDropItemId: "item.wild-herb"`、`lootItemId: "item.beast-material"`、`rewardCurrency: "lowGradeSpiritStone"`。

#### ③ 物品数据字典 (`data/items/items.json`)

### 3.3 缺陷 N1 修复：界面永不出现机器 ID

- **原因分析**：原渲染逻辑简单取 `item.unit` 拼装，而在机器 ID 规范化后，`unit` 变为了 `lowGradeSpiritStone`，导致玩家直视底层标识符。
- **修复方案**：
  在 `renderState()` 及全部事件播报节点中，引入映射检索：
  ```javascript
  const currenciesConfig = (TUNING && TUNING.currencies) || {};
  const cfg = currenciesConfig[item.unit] || {};
  const name = cfg.displayName || "下品灵石";
  const unit = cfg.displayUnit || "枚";
  return `${name} ${formatValue(item.amount)} ${unit}`;
  ```
- **验证结果**：
  左栏随身资产正常渲染为：
  ```
  💎 随身灵石    下品灵石 10 枚
  ```
  界面任意区域（包括三栏界面、日志、气泡、提示词）经检索确认无任何 `lowGradeSpiritStone` 机器键外泄。

### 3.4 缺陷 N2 修复：运行时强校验与写入一致性

- **修正写入**：
  将探索获得灵石的代码严格修正为：
  ```javascript
  currencies.push({ unit: "lowGradeSpiritStone", amount: found });
  ```
  彻底剔除已废弃的 `currency: "下品灵石"` 属性。
- **运行时状态校验器 (`validateState`)**：
  为避免「校验器管得了文件管不了内存」，在 `app.js` 核心生命周期（`saveState` 存档、`loadState` 读档、`applyResponse` 补丁应用、JSON 导入导出）接入统一的运行时守门机制：
  1. **逆向必填反查**：针对角色 19 项核心字段（`id`, `name`, `age`, `background`, `identity`, `spiritualRoot`, `constitution`, `realm`, `cultivationProgress`, `spiritualPower`, `fatigue`, `injuries`, `inventory`, `currencyBalances`, `relationships`, `reputation`, `debts`, `goals`, `activeTasks`），若有任何一项为 `undefined`，立即报错拒绝。
  2. **废弃字段反查**：严禁出现 `vitality`、`spiritRoots`（数组）。
  3. **货币结构动态自检**：遍历 `currencyBalances`，断言 `unit` 为非空字符串、`amount` 为合法数字，且**断言 `currency` 字段绝对不存在**。一旦引擎内部产生非法条目，立即在控制台报错并中断保存，彻底杜绝违规脏数据落盘。
