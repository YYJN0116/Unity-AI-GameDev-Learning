# 修仙游戏设计文档

## 1. 项目名称

修仙世界记录簿 / Xiuxian World Journal

## 2. 项目目标

这是一个以修仙为主题、基于文本交互和 AI 主持的网页式游戏原型。

目标不是一开始就做一个大而全的商业游戏，而是先建立：

- 一个可持续的修仙世界观
- 一个清晰的成长循环
- 一个具备资源管理和风险判断的玩法框架
- 一个让 AI 可以稳定主持剧情的结构化输出方式
- 一个在网页中能够运行、存档、扩展的原型

最终目标：
- 让玩家感受到自己在“修仙世界”中真正成长
- 让 AI 主持者能够持续推进故事
- 让玩家不只是“看故事”，而是“参与世界”

---

## 3. 游戏核心体验

### 3.1 这个游戏的核心是：
- 角色成长
- 资源管理
- 信息获取
- 关系和世界变化
- 以文本 + 结构化状态为主的修仙剧情推进

### 3.2 玩家的核心感受
玩家需要感受到：
- 我在变强
- 我在改变世界
- 我在积累信息与人情
- 我的选择会产生后果
- 每次行动都不是无意义的

---

## 4. 游戏世界观

### 4.1 世界背景
在一片被灵气缠绕的世界中，人类存在于大大小小的修仙门派与世俗势力之间。

灵气并非平均分布，而是集中于不同地区：
- 山脉秘境
- 灵脉谷地
- 宗门山门
- 人间坊市
- 寒墓荒地
- 古旧禁地

凡人可成长为修士，修士可迈向境界层层突破。

### 4.2 主要势力
建议至少建立 4-6 个重要势力：

1. 玄风宗
2. 烈焰谷
3. 月隐门
4. 人间商会
5. 玄海荒地
6. 旧朝残迹

每个势力至少应有：
- 势力背景
- 核心价值观
- 与玩家的关系
- 财力 / 权力 / 资源
- 关键人物

### 4.3 修仙世界的核心法则
- 修炼需要时间和资源
- 功法不等于掌握，需结合体质与悟性
- 奇遇并非奖励，而是风险和机会并存
- 人情、名声、关系会影响行动
- 重大选择可能改变世界状态

## 5. 角色系统设计

### 5.1 角色基础属性
建议角色至少包含以下字段：

- 姓名
- 年龄
- 背景
- 灵根
- 体质
- 境界
- 修为
- 疲劳值
- 伤势值
- 灵石
- 丹药
- 物品
- 人际关系
- 任务状态
- 目标

### 5.2 角色重要属性说明

#### 1. 灵根
例如：
- 火系
- 风系
- 土系
- 雷系
- 木系
- 水系
- 兼修型

灵根影响：
- 适合修炼的功法
- 对环境的适应
- 对法术的稳定性

#### 2. 体质
例如：
- 凡体
- 练体
- 丹脉体
- 玄火体
- 冰魄体

体质影响：
- 承受伤势能力
- 修炼上限
- 适应不同玩法

#### 3. 修为与境界
例如：
- 炼气
- 筑基
- 金丹
- 元婴
- 化神
- 仙境

建议每个境界都有：
- 修为上限
- 突破条件
- 需要准备的资源
- 可能引发的事件

#### 4. 关系系统
建议玩家与 NPC 的关系可以分为：
- 陌生
- 友好
- 亲近
- 信任
- 依赖
- 反感
- 敌意

关系影响：
- 商人是否愿意提供物资
- 师长是否为你保留机会
- 师门是否认可你
- NPC 是否愿意提供信息

## 6. 行动系统设计

### 6.1 核心行动类型
建议至少包含 5-8 类基础行动：

1. 修炼
2. 探索
3. 任务
4. 商贸/交易
5. 结交 / 交谈
6. 试炼 / 战斗
7. 突破
8. 休息 / 闭关

### 6.2 每个行动的设计要点
每个行动都应包含：
- 所需时间
- 所需资源
- 成功条件
- 失败风险
- 可能获得的收益
- 可能引发的事件

### 6.3 动作设计示例

#### 修炼
- 提升修为
- 扣耗灵力
- 可能疲劳值增加
- 可能伤势增大

#### 探索
- 找到灵草、古物、秘境入口
- 可能遇到敌人、奇遇、危机
- 可能获得信息和线索

#### 任务
- 师门任务 / 外门任务 / 委托任务
- 可获得灵石、名声、功法线索
- 可能提升或损害关系

#### 交易
- 购买丹药、灵草、工具
- 卖出废料、奇珍、低价宝物
- 可能被欺骗或被观察

#### 结交
- 维护关系
- 获取情报
- 争取帮助
- 推进剧情线索

## 7. 世界地图设计

### 7.1 建议建立 4-6 个关键地点

1. 后山洞府
2. 山门
3. 坊市
4. 冷泉谷
5. 密林秘境
6. 禁地前沿

### 7.2 每个地点的功能

#### 后山洞府
- 最安全的修炼地
- 适合闭关
- 有较低风险

#### 山门
- 领取任务
- 结交师兄弟
- 获取消息

#### 坊市
- 交易
- 购买资源
- 获取外部消息

#### 密林秘境
- 探索危险区域
- 可能获得法器或功法残片
- 高风险高回报

#### 禁地前沿
- 关键事件地点
- 可能隐藏秘密
- 可能播放故事高潮

## 8. 资源系统

### 8.1 必要资源
建议至少包含：

- 灵石
- 灵力
- 疲劳值
- 伤势值
- 丹药
- 物品
- 人情
- 名声
- 关系值
- 债务

### 8.2 资源的设计原则
- 资源不能只作为“数字展示”
- 必须影响行动
- 必须带来真实后果
- 应该让玩家自己判断风险

---

## 9. 战斗与判定系统

### 9.1 不要求复杂系统
修仙游戏不一定需要真正的战斗数值系统，开始时可以基于"判定 + 风险 + 状态变化"。

### 9.2 战斗原则
- 简单行动成功率高
- 高风险行动需要判断
- 判定依据包括：
  - 实力差距
  - 资源准备
  - 地理环境
  - 情报质量
  - 伤势和疲劳

### 9.3 判定模板
比较简单有效的判定方式：
- 目标行动是否有明确风险？
- 是否需要额外准备？
- 角色是否有优势？
- 是否有信息差？
- 是否会造成伤势或消耗资源？

如果风险存在，就让 AI 主持输出：
- 判定依据
- 成功/失败的后果
- 对资源的影响
- 对剧情和关系的影响

## 10. 事件系统

### 10.1 事件设计原则
- 事件不需要强制所有玩家走同一个主线
- 事件可以是：
  - 机缘
  - 任务
  - 危机
  - 人际冲突
  - 线索
  - 选择题

### 10.2 事件类型
1. 线索事件
2. 商业事件
3. 关系事件
4. 战斗事件
5. 突破事件
6. 世界事件

### 10.3 事件触发方式
可以通过：
- 时间推进
- 地点变化
- 任务状态
- 人际关系变化
- 特定资源达标

## 11. 存档与记录系统

### 11.1 必须有的保存状态
- 角色状态
- 资源状态
- 日记记录
- 任务状态
- 地点状态
- 关系状态
- 世界事件状态

### 11.2 记录内容
建议每次行动后保留：
- 行动概述
- 额外资源变化
- 伤势与疲劳变化
- 关系变化
- 线索获取
- 新的剧情钩子

### 11.3 一个好的存档格式
建议以 JSON 或本地存储结构保存在浏览器中，关键字段如下：

```json
{
  "player": {
    "name": "林云川",
    "realm": "炼气九层",
    "cultivation": 640,
    "spiritStones": 120,
    "health": 90,
    "fatigue": 25
  },
  "world": {
    "day": 2,
    "currentLocation": "后山洞府",
    "log": []
  }
}
```

## 12. AI 主持规则

### 12.1 AI 不能直接无限发挥
AI 主持时需要有固定结构，让它持续输出：

1. 当前局势
2. 角色能观察到的情况
3. 这次行动的具体结果
4. 资源和状态变化
5. 关系变化
6. 3 个可选动作
7. 一个新的剧情钩子

### 12.2 AI 输出模板
建议输出格式如下：

```text
当前局势：

角色状态：
- 修为：
- 灵石：
- 疲劳：
- 伤势：
- 关系：

此次行动结果：
- 发生了什么
- 是否成功
- 带来了什么变化

变化：
- 资源：
- 疲劳：
- 伤势：
- 关系：

可选行动：
1. 
2. 
3. 

剧情钩子：
- 
```

这样可以极大减少 AI 偏离规则的情况。
