# NPC 生成流程

本文规定如何从 `npc-roster.md` 的固定角色位和性格版本生成本局 NPC，并在游戏中维持其行动、知识与关系的一致性。它不改写角色库，不把 NPC 变成服务玩家的剧情工具，也不替玩家决定角色关系。

## 1. 生成原则

- 角色库定义故事位置和性格版本；姓名、年龄、背景、能力、初始关系等具体资料按本局情境生成并记录。
- 性格版本是行为倾向，不是强制台词或固定结局。NPC 可以成长、改变或与玩家和解，但变化须有经历和动机支撑。
- NPC 有自己的目标、资源、关系、记忆和有限知识。不得无缘无故全知、瞬移、改变立场或只为推动玩家剧情而行动。
- NPC 的出场不代表玩家必须接受任务、建立感情、结盟或与其敌对。
- 不把未确认的 NPC 资料说成原有正史。新生成 NPC 标记为“本局生成”；是否加入共享角色库由玩家另行决定。

## 2. 生成前确认

开始新局时确认：

1. 是否启用 `npc-roster.md` 的五个固定位置：女主型、死对头型、宿敌型、恩人/导师型、情敌/反派型。角色位是可用设计槽，不是每局都必须登场的强制阵容。
2. 每个启用角色位是随机选择、玩家指定，还是暂不生成。
3. 是否有需要保留的 NPC；没有明确保留的角色按新局约定重新生成。
4. 玩家对关系、恋爱、背叛、竞争等内容的偏好或边界（如适用）。

玩家明确指定的性格版本或保留项优先于随机分配。若某角色位的现有版本数少于角色库的目标规模，不得声称该库已满足 10–15 种版本；可以使用现有版本，或在玩家授权后另行提出新增版本供确认。

## 3. 单个 NPC 的生成步骤

### 第一步：选择角色位和性格版本

从角色库选择一个适合本局地点、势力和故事功能的版本。可随机选择，但记录选择结果。不能仅为了制造戏剧冲突而让多个 NPC 拥有相同功能；如有重叠，需说明各自差异。

### 第二步：建立因果背景

为该版本补充与本局世界相容的身份、经历和当前处境。背景只提供能解释其目标与行动的必要信息，不需要预先写满人生史。若涉及宗门、家族、秘密身份、仇怨或重大创伤，检查其与世界配置是否一致，并标明哪些信息属于公开、角色已知或主持端隐藏。

### 第三步：生成角色资料

按剧情需要填写：

- 姓名、年龄、身份/背景、所属地点或势力
- 当前境界、能力与资源（有冲突风险时必须与本局规则及玩家角色状态相容）
- 外显性格、核心动机、短期目标和长期目标
- 主要顾虑、限制或代价
- 与玩家角色的初始关系及形成原因
- 已知事实、传闻、误解和未知事项
- 可能采取的行动，以及促使其改变行动的条件

不需要出场的字段标记“暂未设定”，不要为了填表而虚构会影响剧情的秘密。

### 第四步：检查角色位与世界的适配

确认 NPC 的年龄与身份合理；能力和资源有来源；目标能由其经历解释；初始关系不预设玩家已经做过的事；角色知识来自亲历、可靠消息或合理推断。若 NPC 强于玩家，行动后果仍须符合实力差距、环境、情报和双方目标，不得靠任意削弱 NPC 或玩家来服务剧情。

### 第五步：记录并呈现

将完整 NPC 状态写入本局记录。玩家可见描述只包括角色可观察到的特征和已知信息；隐藏动机、未揭示身份和主持端判断单独保存。NPC 初次出现时，提供可互动场景和玩家能察觉的线索，不直接展示其完整档案。

## 4. NPC 状态与行动追踪

每个已启用 NPC 至少维护：

- 当前地点、状态、所属关系
- 目标、计划、资源与能力边界
- 对玩家及其他 NPC 的关系和变化原因
- 知识账本（亲历、收到的信息、推断、误解、未知）
- 近期行动、行动时间、结果及未完成事项
- 性格版本的核心特点，以及已经发生的合理变化

NPC 在玩家不在场时仍可行动，但每项重要变化要有时间、动机、可用信息、能力和资源依据。玩家未获知的变化不能直接写入玩家角色的知识；之后应通过可解释的消息或观察让其获知。

## 6. 关系变化规范

关系不因角色位或性格版本自动升级。每次显著变化都记录行动/事件、双方可知情境、变化方向、游戏内时间和可能的后续影响。爱情、信任、敌意、依赖等关系状态须由互动逐步形成；NPC 保留自己的意愿和边界。玩家拒绝某条关系线，不应自动触发惩罚或强制剧情。

## 7. 生成检查表

- [ ] 角色位与性格版本来自角色库，或明确标记为经确认的新版本。
- [ ] 玩家指定和保留的 NPC 没有被随机结果覆盖。
- [ ] NPC 的目标、能力、资源、知识和关系彼此相容。
- [ ] 角色未知的秘密未混入公开描述或玩家存档。
- [ ] NPC 的行动有动机、时间、信息和能力依据。
- [ ] 关系变化有具体互动原因，不强迫玩家接受剧情关系。
- [ ] 测试 NPC 和临时人物没有未经确认地写入共享设定库。
