## 2. 逐项答复《02 报告》七大复审问题（O1–O6）

### 问题 1 (O1)：`data/` 采用 bundle 方案，还是放弃 `file://` 支持？
> **答复：坚决采用 `data-bundle.js` 方案，誓死守住「双击即玩」的零门槛核心体验！**
- **架构方案**：
  - `data/*.json`（以及未来的 `events/*.json`）作为**编剧侧创作与静态校验器（Validator）的源文件**。
  - 增加轻量级打包脚本 `scripts/build-data.js`（纯 Node 原生，耗时 < 50ms），将 `data/*.json` 合并输出为 `可运行测试第一版/data-bundle.js`（挂载在 `window.XIUXIAN_DATA`）。
  - `index.html` 引入 `<script src="data-bundle.js"></script>`，浏览器双击以 `file://` 打开时完全不触发 CORS，彻底解决跨域白屏问题。
  - 在后续 CI 与 `npm test` 中自动串联 `build-data.js`，保证编译透明无感。

### 问题 2 (O2)：接受「同一 tick 多 main 命中 = 校验错误」与「ambient 走加权随机」吗？
> **答复：完全接受！此前的字典序确实会扼杀权重，多 main 互撞必须是致命内容 Bug。**
- **具体实施**：
  - `ambient` / `side` 冲突消解：采用种子化加权随机（结合 R8 PRNG）。
  - 同一 tick 出现多个 `main` 节点满足条件：
    - **静态校验期**：校验器分析前置依赖条件，若发现无互斥条件的并行 main 节点，直接报 Warning/Error。
    - **运行时**：调度器检测到多 main 命中直接抛出致命异常并记录日志，绝不静默挑一个。

### 问题 3 (O3)：RNG 续接采用 cursor 还是计数器派生？
> **答复：采用 `state.rngSeed` + `state.rngCursor`（已调用次数记录器）方案。**
- **机制落地**：
  - 状态新增持久化字段：`rngSeed: number`、`rngCursor: number`。
  - 引入轻量级确定性 PRNG（`Mulberry32`）。
  - 每次消耗随机数，`rngCursor++`。读档恢复时，根据 `seed` 初始化后，先向前步进 `rngCursor` 次，保证后续产生的随机数序列与不存档连续跑完**完全一致**。
  - **验收测试**：编写专项测试用例——*跑 50 次随机行动并存档 → 重新载入存档再跑 50 次 → 断言其结果与连续跑 100 次的后 50 次分毫不差*。

### 问题 4 (O4)：接受「消耗类走 `requires`、越界即报错、钳制仅限可恢复量」吗？
> **答复：完全接受！消除机制双标，严禁对消耗性资源做掩耳盗铃式的静默钳制。**
- **机制落地**：
  - 所有资源消耗型操作符（如 `currency.add` 减灵石、`item.remove` 扣道具），其所在的 choice 必须配置等价的 `requires`（如 `{"gte": ["currency.lowGradeSpiritStone", 3]}`）。
  - 执行期若因未知 Bug 发生透支扣至负数：**立即 Hard Fail，中止该 Effect 并报错**，绝不静默钳制到 0。
  - 仅对生理与成长可恢复量（`fatigue` 疲劳 0~100、`cultivationProgress` 修为 0~100）允许区间钳制，且发生钳制时在 `ledger` 中明确标注 `"clamped": true`。

### 问题 5 (O5)：M0 是否可以不引入任何检定数学？
> **答复：可以且必须！M0 绝不在代码中硬编码任何检定公式。**
- **机制落地**：
  - M0 阶段保持纯机制骨架，推演层仅保留桩函数（Stub）。
  - 严禁把 `1d10 + 灵力` 这种不成立的数学写入代码。
  - 静候小肥交付《数值基线 `tuning.json` 草案》中的“归一化检定属性层（1–5 级）”与“DC 难度基线表”后再行接入。

### 问题 6 (O6)：F5（炼气九层突破断头路）是否登记为 M3 工作项？
> **答复：已正式建档立项！**
- **任务编号**：`ISSUE-F5: 突破至筑基期状态跃迁与筑基剧情节点接入`。
- **排期归属**：正式挂载在 **M3 里程碑（第一卷接入）**，作为主线终局突破的大事件处理。

### 问题 7 (§3.1)：`data/world.json` 是否按「骨架 + 占位标记」处理？
> **答复：完全照办！绝不把前代 AI 随口编造的占位地名固化为正史数据。**
- **格式规范**：
  `continents`、`regions`、`locations`、`factions` 仅放空数组与通用 Schema，仅插入一条通用占位符：
  ```json
  {
    "id": "loc.placeholder-01",
    "name": "【占位地点】",
    "regionId": "region.placeholder-01",
    "canon": false,
    "placeholder": true
  }
  ```
