## 2. 当前挂起与外部依赖事项说明

在 M1 事件管线正式开工前，目前有两个处于**挂起待决 / 交付中**的事项，均已安全隔离，不阻碍核心引擎管线的推进：

### 2.1 事项一：经济手感最终裁定（YY 裁定中）
- **现状**：
  在《11》与《12》报告中，按小肥建议对齐了《16》基准（补气丸 2 灵石，日常任务 1–2 灵石）。3 个游戏日实测结果为：**收入 +5，支出 -5，期末结余 10（净变化 0）**。
- **裁定议题**：
  小肥指出“净变化 0 意味着玩家永远无法通过日常积累攒够修炼室费用（1–4 灵石）”。提出三种可能的手感方向：
  - **选项 A（如履薄冰）**：维持净 0，生存压力拉满，但可能导致中前期成长卡死；
  - **选项 B（缓慢积累）**：微调任务报酬至 `[2, 3]` 或降低生活成本，三日可攒 2–3 灵石；
  - **选项 C（推荐 · 靠事件开口子）**：日常维持净 0，而将灵石盈余作为偶发奇遇、任务重赏或人情往来的进项，契合设定集 34“资源阶段性卡关”的节奏。
- **当前处理**：
  **遵照 YY 指示，引擎端本轮暂不动经济参数，静候 YY 最终裁定**。待裁定明确后，仅需调整 `tuning.json` 即可秒级生效。

### 2.2 事项二：正史开局区域与正式人物卡（编剧侧交付中）
- **现状**：
  当前数据层中运行的是供联调测试用的骨架数据（`placeholder-starter.json`、`loc.placeholder-01`、`region.placeholder-01`、`npc.placeholder-guide`）。

### 3.1 阶段一：事件加载器、正史锚点与 DSL 解释引擎研发（预计 8 个工作日，2026-10-17 起）
1. **事件目录契约（《10 定稿》§7.5）**：
   - 在 `可运行测试第一版/data/` 下建立事件目录，**一事件一文件，文件名必须严格等于事件 id**：
     ```
     data/events/
     ├── main/       ← 主线事件节点 (例：main.ch01.01.json，id 对应 main.ch01.01)
     ├── side/       ← 支线事件节点 (例：side.ch01.01.json，id 对应 side.ch01.01)
     └── ambient/    ← 偶发环境事件 (例：ambient.<regionSlug>.01.json)
     ```
   - **单文件上限 64 KB**，超过即必须在设计上拆分节点；
   - **加载确定性**：加载事件节点必须按 `(kind, chapter, priority, id)` 四元组确定性升序排序后建立内存索引，**严禁依赖操作系统底层文件系统返回顺序**；
   - 打包工具 `build-data.js` 自动打包事件进入 `data-bundle.js`，并生成 `id → 来源文件` 完整反查索引与依赖清单。
2. **正史锚点独立数据源（《10 定稿》§7.1）**：
   - 新增 `data/canon/` 目录，存放正史不可变锚点；
   - 字段标准：`id`（格式 `novel.ch<NN>.anchor.<slug>`）、`chapter`、`summary`、`fixedOutcome`、`observableAt`、`relatedEventIds`；
   - 事件节点**仅通过 `canonAnchorId` 引用锚点**，严禁内联小说长正文；
   - 触发优先级锁定：**正史锚点 > `main` > `side` > `ambient`**；正史锚点属客观世界事实，不计入 `main` 冲突计数。
3. **Condition DSL 解释器（含《10 定稿》§7.3 误解平行态）**：
   - 实现纯逻辑求值，支持 `all`、`any`、`not` 递归复合判断与标准比较操作符；
   - 落实 `understanding` **平行态「误解」**：
     - 六阶梯（未接触 → 初识 → 入门 → 熟练 → 精通 → 自成体系）维持不变；
     - `误解` 仅能通过 `understanding.set` 显式附带 `evidence` 写入，不进阶梯递进；
     - 处于 `误解` 态时，任何 `gte: 熟练`（及以上）的条件判定一律求值为“不满足”（非异常报错）。
4. **Effect DSL 组级事务回滚执行器（《10 定稿》§7.2）**：
   - **事务边界明确为：整个 outcome 组**（`onSuccess` / `onFail` / `defaultOutcome` 等各自独立成组）；
   - **整组原子性**：组内任一条 Effect 导致资源量（灵石/背包）越界，**整组彻底回滚、ledger 不落账、事件不推进**，并向玩家与控制台明确报错中止；**严禁静默回滚**；
   - 运行期每完成一个合法 outcome 组，统一向 `ledger` 写入明细流水。
5. **测试夹具落位（《10 定稿》§7.4）**：
   - 夹具文件统一存放于 `tests/fixtures/`，严禁混入 `data/events/`；
   - `scripts/build-data.js` 新增 `--fixtures` 编译开关，默认构建不打包测试夹具，CI 测试时显式开启；
   - 校验器**不设 `test.` 前缀白名单**，杜绝测试豁免导致正式事件漏检。

### 3.2 阶段二：校验器硬阻断与共享 ID 校验（预计 6 个工作日）
将《10 定稿》§4.4 的 10 项校验规则与 §7.6 全面写入 `scripts/validate-schema.js`，构建 CI 硬阻断防线：
1. **规则 6（唯一性保护）**：同一 tick 下多个 `main` 节点同时满足激活条件时，**判定为静态编译错误**，禁止留在运行时随机消解；
2. **规则 7（Hazard 事前预警校验）**：`hazard.declared: true` 而 `hazard.foreshadowed: false` 时，**校验直接阻断报错**；普通检定严禁携带 hazard 字段；
3. **规则 8（Fail-Forward 失败推进校验）**：带有 `check` 的选项，其 `onFail` 必须提供合法的 `next` 或显式 `blockReason`，杜绝死胡同；
4. **规则 9（条目级复合结构校验）**：对所有新增事件引用的背包、货币、关系进行深度条目级字段反查；
5. **小说/游戏共享 ID 登记校验（§7.6）**：事件引用的 `npcId` / `locationId` / `factionId` / `topicId` 必须登记在 `剧本文档/03_小说与游戏共享ID规范_v1.md` 登记表中，引用未登记 ID 直接校验阻断；
6. **孤儿引用反查（§7.1）**：静态反查引用 `canonAnchorId` 的合法性，删除或修改锚点后精准提示所有断链事件。
