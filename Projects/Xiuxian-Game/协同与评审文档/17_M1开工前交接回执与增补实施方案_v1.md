### 2.1 正史锚点独立存放（§7.1）
- **数据源目录**：建立 `data/canon/`，每个锚点独立单条，文件命名与内部 `id` 对齐（`novel.ch<NN>.anchor.<slug>.json`）；
- **字段白名单**：`id`, `chapter`, `summary`, `fixedOutcome`, `observableAt`, `relatedEventIds`；
- **引用机制**：事件节点仅包含 `canonAnchorId` 字符串键，杜绝内联长文本正文；
- **优先级仲裁**：推演器调度优先级严格锁死为：**正史锚点 > `main` > `side` > `ambient`**。锚点属于客观世界演进，不计入 `main` 的冲突互斥计数；玩家不在场时，锚点固定事件照常在后台推演。
- **断言测试**：编写专项测试验证：删除任一锚点时，校验器精准定位所有悬空节点；同一 tick 存在一个锚点与两个 `main` 时精准报错。

### 2.2 Effect 事务边界与整组原子回滚（§7.2）
- **事务边界界定**：事务粒度严格对齐到**单个 outcome 组**（包括 `onSuccess`, `onFail`, `onCriticalSuccess`, `onCriticalFail`, `defaultOutcome`）；
- **原子性保障**：
  ```javascript
  // 伪代码执行逻辑
  function executeOutcomeGroup(state, outcomeGroup) {
      const snapshot = deepClone(state); // 状态镜像
      const pendingLedger = [];
      try {
          for (const effect of outcomeGroup.effects) {
              applyEffect(snapshot, effect, pendingLedger); // 内部发生负数越界直接 throw OverflowError
          }
          // 整组全部成功，提交事务
          commitState(state, snapshot);
          state.ledger.push(...pendingLedger);
      } catch (err) {
          // 整组原子回滚：ledger不落、事件不推进、UI显式警告
          logRollbackWarning(err);
          throw new OutcomeGroupAbortedError(err);
      }
  }
  ```
- **禁止静默回滚**：回滚发生时，必须在控制台及界面抛出显式中止提示与越界位置，严禁任何形式的静默吞错；
- **静态预检**：能在编译期/校验期通过静态值推导判定的越界（如扣减固定数量灵石），直接在静态校验期阻断。

### 2.3 `understanding` 平行态「误解」（§7.3）
- **非递进平行态**：取值域在“未接触 → 初识 → 入门 → 熟练 → 精通 → 自成体系”六阶梯之外，增设独立平行态 `误解`；
- **写入门控**：常规递进类操作（如学习、突破）禁止产出 `误解`，仅允许由 `understanding.set` 显式写入，且 Schema 强制要求携带 `evidence`（论据文本/来源事实）；
- **判定求值**：在 Condition 求值器中，若当前角色对该 `topicId` 处于 `误解` 状态，任何包含 `gte: 熟练`（或以上）的条件直接判定为 `false`（不满足），而不抛出异常；
- **界面修仙感呈现**：在 UI 状态展示中，`误解` 单独以警示标记（如“心生偏差 / 认知谬误”）呈现，绝不渲染为递进链条上的“第七阶”。

### 2.4 测试夹具落位与构建开关（§7.4）
- **物理路径隔离**：所有测试夹具统一存放于 `tests/fixtures/`，严禁任何夹具进入正式 `data/events/` 目录；
- **构建脚本升级**：
  - `node scripts/build-data.js`：默认构建**绝对不扫描、不打包**夹具文件；
  - `node scripts/build-data.js --fixtures`：显式开启夹具打包，夹具以真实打包形式并入内存 bundle，供测试用例调用；
- **零白名单原则**：校验器 `validate-schema.js` **坚决不开设 `test.` 前缀白名单**，确保正式事件无法通过取巧前缀规避严格校验。

### 2.5 `data/events/` 目录契约与确定性加载（§7.5）
- **命名规范**：**一事件一文件，文件名必须等于 id**（如 `main.ch01.01.json` 对应 `id: "main.ch01.01"`；`side.ch01.01.json` 对应 `id: "side.ch01.01"`；偶发事件对应 `ambient.<regionSlug>.01.json`）；
- **目录层级扁平化**：仅保留 `main/`, `side/`, `ambient/` 三个子目录，章节由事件内部的 `chapter` 属性声明，**严禁通过子文件夹嵌套章节**；
- **单文件体积硬顶**：单文件体积上限设为 **64 KB**，超出该上限则在 CI 构建阶段直接报错阻断，倒逼编剧与实现侧拆分节点；
- **加载顺序确定化**：事件加载器在读取全部文件后，必须严格按照 `(kind, chapter, priority, id)` 四元组进行确定性升序排序后再构建运行时索引，**彻底杜绝任何依赖文件系统读取顺序的不确定性**；
- **打包索引生成**：`build-data.js` 将在打包产物中自动输出两张清单：
  1. `eventId → 来源文件相对路径` 的反查索引；
  2. `eventId → 依赖的资源清单（npcId, locationId, canonAnchorId 等）`。

### 2.6 小说/游戏共享 ID 校验（§7.6）
- **契约基准**：严格以 `剧本文档/03_小说与游戏共享ID规范_v1.md` 中的登记表为准绳；
- **反向强校验**：`validate-schema.js` 扫描所有事件节点中的 `npcId`, `locationId`, `factionId`, `topicId`，一旦发现未在登记表中注册的 ID，直接报错阻断构建，防止代码中凭空臆造角色或宗门。
