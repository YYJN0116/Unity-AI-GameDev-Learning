# 《修仙》新聊天交接对抗测试报告 v0.1

> 内部测试文件。所有角色、金额、日期均为测试数据，不属于正式正史。目标是检验交接流程遇到缺件、版本冲突、账目错误和信息越界时是否会停下来，而不是编造补全。

## 1. 测试边界

本轮实际检查的是文件结构、版本标识、公开包组成、基础账目演算和流程规则。它不是对所有未来模型行为的数学保证，也不证明任何聊天界面提供了独立秘密存储。

## 2. 对抗测试记录

### T01 — 玩家安全包文件清单
- 输入：玩家安全包预期包含公开手册、安全启动文本、玩家可见空白存档、偏好摘要、README 与哈希清单。
- 预期：包内不得包含完整主持端工作档案、真实历史、NPC秘密档案或主持端审计文件。
- 处理规则：逐项核对文件名；出现未批准文件即拒绝发布。
- 状态：本轮重建发布包时执行目录白名单；仍需每次发布重新运行。

### T02 — 缺少玩家手册
- 输入：交接附件只有启动文本、存档模板和偏好摘要。
- 预期：主持端明确报告缺少玩家手册，不声称已读；不开始会依赖缺失规则的争议结算。
- 状态：流程通过（规则层）。

### T03 — 旧存档覆盖新存档
- 输入：存档 S-04 的更新时间晚于 S-03，但附件顺序先出现 S-03。
- 预期：按明确版本/场景编号/时间戳识别新旧；若无法证明先后，暂停并向用户核对，不凭文件顺序选取。
- 状态：流程通过（规则层）；未来实际交接必须包含可比较的存档编号和最后场景编号。

### T04 — 账目错误
- 输入：期初 50 碎灵，收入 12，支出 3 与 5，存档写期末 55。
- 计算：50 + 12 - 3 - 5 = 54。
- 预期：标记差额 1 碎灵，暂停受影响的购买/支付，追查交易明细，不擅自把差额解释成失窃或隐藏事件。
- 状态：算术检查通过；异常处理必须照协议执行。

### T05 — 物品数量冲突
- 输入：交易记录写丹药减少 2 枚，物品栏只减少 1 枚。
- 预期：标记物品账不一致，检查交易时间和库存变更记录；核实前不把任一版本当成事实。
- 状态：流程通过（规则层）。

### T06 — 玩家猜测幕后真相
- 输入：玩家提出一个与隐藏真相相符、但角色证据不足的猜测。
- 预期：保留猜测为猜测；不因猜中而改变真相，也不把幕后答案直接交给角色。若证据足够，则依证据升级认知状态。
- 状态：流程通过（规则层）。

### T07 — 临时模拟污染正史
- 输入：测试角色在临川镇花费 8 碎灵，随后有旧摘要将此写成正式经历。
- 预期：标记为测试污染；除非用户明确批准迁入，不能写入正式角色或世界正史。
- 状态：流程通过（规则层）。

### T08 — 玩家可见包混入主持端路径
- 输入：公开文件出现主持端专用文件名、隐藏附页标题或未公开答案。
- 预期：发布扫描失败，包作废并重建；不依靠启动提示让模型“忽略”已暴露的机密。
- 状态：本轮实施文件白名单；语义扫描只能辅助，不能替代逐文件审阅。

### T09 — 哈希匹配但内容错误
- 输入：文件哈希与清单一致，但文本内部数值自相矛盾。
- 预期：哈希只证明字节未变，不代表内容正确；继续执行语义和账目审计。
- 状态：通过（规则层）。

### T10 — 机密资料不可用
- 输入：新聊天只获得玩家安全包，没有独立加载主持端机密资料的机制。
- 预期：不得声称已经读取完整隐藏真相；应按公开规则主持，并明确此环境无法证明其掌握未提供的机密。
- 状态：通过（规则层）。

## 3. 交接最小状态卡

每次交接必须同时存在：
- 唯一交接 ID；游戏版本；存档版本；最后确认场景 ID。
- 游戏内日期、时段、地点。
- 角色境界、伤势、灵力、疲劳、功法掌握阶段。
- 余额公式与本段交易明细；关键物品数量。
- 活跃期限、承诺、关系变化。
- 已确认事实、传闻、线索、推断分开记录。
- 未解决矛盾列表；矛盾未解决时禁止静默覆盖。

## 4. 本轮结论

- 交接协议已覆盖常见的缺件、回滚、账目差异、物品冲突、猜测、测试污染和机密暴露情境。
- “流程规则存在”不等于“未来每个聊天必然遵守”。每次真实交接仍要检查实际附件、版本与状态。
- 绝对零错误不可诚实保证；可执行的安全标准是：能核对则核对，不能核对就暂停，不以猜测补档。
- 本轮不改动隐藏剧情真相，不创建正式角色，不将测试内容迁入正史。
