# 《修仙》跨档案矛盾审计 v0.1

> 记录已发现的文档层级问题及修复办法；不把尚未测试的部分误报为已完成。

## 1. 已确认的问题与处理
### A. 索引版本/文件数落后
旧索引可能未计入新聊天启动文本及后续模块。每次打包前按实际目录清点，索引的文件数必须由目录结果确认，不手写猜测。

### B. 玩家手册与主持端数值状态不同
公开手册说明原则；主持端数值基线含暂定价格与耗时。开局前确定适用的公开基线摘要。角色不自动知道未询价的精确价格；一旦价格或路线在游戏中确认，就写入地区卡和存档，不随意追溯更改。

### C. 时间单位定义缺口
统一默认 1刻=15分钟、4刻=1时辰；地方可换称呼，但主持端账本必须换算一致。

### D. 高阶能力尚未逐项量化
飞行、神识、空间能力已有原则边界，但并非每项术法/法器都有精确数值。首次重要出现时记录范围、成本、限制、可见迹象与反制方式，不假装旧文件已有完整数值。

## 2. 不应误报为已完成
- 隐藏历史有稳定骨架，不等于完整年代史已完成。
- 势力档案与人物原型不等于全世界组织/人物名册完整。
- 结局已有分支原则，不等于每个结局都写成固定剧本。
- 经济有基础参考价，不等于所有商品和法器都有完整价目表。
- 战斗有裁定协议，不等于每种术法都有伤害公式。
- 有启动文本不等于角色已创建或游戏已开始。

## 3. 正式开局前阻塞项
1. 玩家手册术语与主持端境界顺序一致。
2. 玩家确认是否采用临川镇。
3. 游戏日期、当地时辰与初始货币关系确定。
4. 角色身份和初始资源经玩家确认。
5. 玩家可见存档与主持端隐藏状态分开。
6. 启动文本与档案包版本一致。
7. 至少实测购买、训练、受伤、调查失败、长闭关和拒绝委托六种场景。

## 4. 冲突优先级
1. 玩家在游戏中明确确认且已发生的事实；
2. 最新变更日志；
3. 正式玩家规则与已公布地区数据；
4. 主持端执行规则；
5. 未定稿草案。
高优先级与低优先级冲突时修正草案并记日志，不回溯篡改玩家经历。
