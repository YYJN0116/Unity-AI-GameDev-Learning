# 《修仙》角色创建与首日验收测试 v0.1

> 测试用途：正式开局时逐项执行。本文不是角色卡，不产生正史；任何模拟数据均需标注“测试用”。

## A. 角色创建验收

1. **授权**：确认玩家自建、主持端提案后确认，或玩家明确授权随机生成。未授权不锁定角色背景。
2. **摘要完整**：姓名/称呼、年龄、出身、境界、修炼路线、已知灵根/体质、技能阶段、身体状态、近期目标、长期愿望/困扰、重要关系。未知字段写“未知/尚未确认”，不随意补全。
3. **资源可重算**：逐项列现金、凡俗货币、物品数量与来源；每个初始物品必须能由背景、交易或明确赠与解释。
4. **能力有边界**：灵根、体质、悟性、经验分开；功法和技能阶段不因角色背景自动越级。
5. **确认后落档**：角色摘要得到确认后才建立正式存档，并记录交接 ID、游戏版本、存档版本。

## B. 第一幕验收

- [ ] 明确游戏内日期/时段与地点。
- [ ] 至少三个角色可感知细节；不得把推断伪装成观察事实。
- [ ] 给出当前限制、至少两个不同方向的可能行动，并明确行动菜单不封闭。
- [ ] 不强迫接任务，不倾倒完整世界历史。
- [ ] 高风险只提前提示角色合理能察觉的部分。

## C. 首日账目验收

每个行动记录：开始时段、耗时、行动结果、收入、支出、物品增减、状态变化、NPC获得/使用的信息。时间不得重复计入。

现金复算：`期末余额 = 期初余额 + 收入 - 支出`。

库存复算：`期末数量 = 期初数量 + 获得数量 - 使用/消耗/转交数量`。食品必须记录具体份数；购买与食用是两次不同的状态变化。服务（如住宿）不加入物品栏。

## D. 首日结束放行

- [ ] 时间线无重叠或无解释跳跃。
- [ ] 现金与物品数量守恒，无法解释的差额先暂停并查账。
- [ ] 技能成长有训练和反馈证据；没有自动升级。
- [ ] NPC只根据自身知识行动。
- [ ] 事实、传闻、线索、推断分别记录。
- [ ] 玩家可见存档不包含主持端隐藏状态。
- [ ] 测试用角色、地点、物价与事件没有迁入正式正史。

若任一关键项未通过，记录问题并修复，不得把测试结论写成“全部通过”。
