# 《修仙》开局前跨文件整合审计 v0.1（v1.3）

> 范围：核对 v1.2 工作档案中与正式开局、玩家安全包和首日模拟直接相关的文件。此审计不宣称完成真实新聊天端到端测试，也不把测试场景转为正史。

## 1. 发现并修复的阻塞问题

### I-01：玩家安全启动文本引用了安全包中并不存在的主持端文件
- 原问题：启动文本要求优先读取行动判定协议、数值基线、角色创建协议、地区草案、矛盾审计和整合检查表，但玩家安全包的白名单没有这些文件。
- 风险：新聊天可能误报文件已读取，或用户误以为这些内部规则都随安全包提供。
- 修复：启动文本现在要求只核对实际收到的玩家安全文件；缺件必须明示；不声称读取未提供的主持端文件。
- 状态：文本层已修复；真实新聊天附件读取仍待实际测试。

### I-02：玩家安全交接指南曾要求把完整机密档案包上传到游戏聊天
- 原问题：指南一处要求上传完整工作包，另一处又警告不要将机密资料放进玩家可见聊天，存在直接冲突。
- 风险：隐藏真相、NPC秘密与结局条件可能直接泄漏。
- 修复：指南改为完整工作包仅作本地/受控主持端备份；玩家可见聊天只使用独立玩家安全包。没有真正隔离机制时，不把机密包放入玩家可见上下文。
- 状态：文本层已修复；平台是否支持任何特定的独立机密加载方式不作假设。

### I-03：玩家手册写明“开局前说明本地时间体系”，但地区和日历仍未正式选择
- 判断：不是规则自相矛盾，而是有意保留的开局门槛。
- 处理：不擅自把临川镇、初秋或测试角色写成正式正史。正式开始前由玩家选择/授权地点和角色生成方式，再明确游戏日期、当地时间叫法、初始货币与资源。
- 状态：保留为正式开局前待确认项。

### I-04：首日模拟的“补给一份”与具体食物份数尚未完全绑定
- 判断：测试账目中的现金守恒正确，但库存消耗记录还不够细。
- 处理：正式游戏中，购买食品时记录名称、份数、每份规格；食用时单独扣除。不得把购买自动视为吃完，也不得把“补给”同时算作铜钱与碎灵两种货币支出。
- 状态：流程规则已明确；首日模拟仍作为部分通过，不回写为正式角色记录。

## 2. 跨文件一致性结果

| 检查项 | 结果 | 证据/说明 |
|---|---|---|
| 境界顺序 | 通过（本轮抽查） | 玩家手册与角色创建协议采用相同顺序：感气、炼气一至九层、筑基、金丹、元婴、化神、炼虚、合体、大乘、渡劫 |
| 时间换算 | 通过（本轮抽查） | 玩家手册与行动经济校准均采用 1刻约15分钟、4刻为1时辰；一天按12时辰记账 |
| 货币换算边界 | 通过（本轮抽查） | 1低阶灵石=10碎灵；铜钱与灵石没有固定兑换率 |
| 技能成长 | 通过（本轮抽查） | 技能阶段依训练、反馈和可复核表现，不按天数自动升级 |
| 测试角色/地点隔离 | 通过（文档声明） | 首日模拟明确标注临时角色、临川镇和示例价格非正史 |
| 玩家安全包与机密包分离 | 文档修复后通过待打包复核 | 必须使用明确白名单重新生成并扫描 |
| 真实新聊天接手 | 未测试 | 需要实际上传安全包到新聊天，核对接收文件和状态；不能在此报告为通过 |

## 3. 首日账目复核

临时演练数据：初始50碎灵，工作收入12碎灵，补给支出3碎灵，住宿支出5碎灵。

`50 + 12 - 3 - 5 = 54碎灵`。现金账目守恒。

此算术通过不代表所有库存细节通过；食物份数和消费动作仍需分开记账。该角色与地点不进入正式正史。

## 5. 本轮结论

v1.3 修复了两个高风险交接文档矛盾，并明确了首日库存粒度和正式开局待确认项。规则与文件流程比 v1.2 更一致，但仍不能标记为正式开局已放行：真实新聊天端到端测试、正式地点/日历/角色确认尚未完成。
