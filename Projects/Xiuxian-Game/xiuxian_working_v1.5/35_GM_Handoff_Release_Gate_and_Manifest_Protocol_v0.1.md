# 《修仙》新聊天交接发布门槛与双包校验协议 v0.1

> 主持端强制流程。用户要求交接尽可能可靠；本协议以减少泄漏与状态丢失为目标，但不作“绝对零错误”的虚假保证。任何发布前检查失败都应停止交接，而不是假装通过。

## 1. 核心原则：不靠记忆，靠可验证文件

新聊天必须以明确版本的文件作为状态依据，不依赖“模型应该记得之前聊过什么”。每次正式交接建立唯一交接 ID、游戏版本、存档版本和文件清单。临时模拟必须明确标记为非正史。

## 2. 永远分成两个发布包

### A. 玩家安全包（可以上传到正式游戏聊天）
只包含：
1. 玩家安全启动文本。
2. 已清理的玩家手册公开版。
3. 当前玩家可见存档（首次开局则使用已清理的空白模板）。
4. 玩家可见剧情回顾/事件记录（只含角色已知内容）。
5. 公开体验偏好摘要：标准硬核、混合式战斗、因果优先、标准风险、均衡叙事。
6. 发布清单与文件校验信息（不含秘密路径、秘密文件名或秘密摘要）。

禁止放入：`01_GM_True_History.md`、任何主持端人物真实动机档案、秘密事件状态、未触发结局条件、GM 隐藏附页、主持端压力测试中暴露真实答案的部分，以及包含这些信息的完整工作档案 ZIP。

### B. 主持端机密包（不得上传到玩家可见聊天）
包含隐藏历史、秘密人物动机、幕后事件状态、GM 连续性审计与本协议等内部文件。必须单独存放、单独命名、单独校验；不得将机密包与玩家安全包合并成一个“方便上传”的压缩包。

## 3. 玩家安全包制作步骤

1. 从最新正式工作版本复制文件到全新临时目录，不在旧包上覆盖。
2. 手工审核公开手册和存档：删除隐藏附页、主持端注释、GM-only 路径与秘密答案。
3. 对每个文件执行“角色知识测试”：角色不可能知道的事实必须删除或改写为已知传闻/未解问题。
4. 对事件回顾执行事实分类：已确认事实、传闻、线索、角色推断分栏，不把推断升级为事实。
5. 检查体验偏好是否同步，且不包含任何剧情秘密。
6. 生成玩家安全包清单：文件名、版本、用途、SHA-256 校验值；清单本身只列玩家安全包文件。
7. 在压缩包中逐一列出内容，并搜索敏感关键词、GM-only 标记、隐藏附页标题与机密文件名。
8. 对压缩包执行完整性测试。任一步失败，作废该包并重建。

## 4. 新聊天接手步骤

新聊天收到玩家安全包后必须先：
1. 列出实际收到的文件名；未收到的文件不得声称已读取。
2. 确认交接 ID、版本、存档最后更新时间。
3. 复核角色位置、游戏时间、境界、伤势、灵力、疲劳、功法掌握、物品、货币和未结期限。
4. 复核余额：期初余额 + 收入 - 支出 = 期末余额；逐项核对物品增减。
5. 复核事实/传闻/推断分层和 NPC 知识边界。
6. 如果关键信息缺失或互相矛盾，暂停推进受影响事项，明确列出缺口；不得自行编造来填补。
7. 只在校验通过后继续游戏，并先用简短状态摘要让用户确认没有错接角色或时间线。

## 5. 机密真相隔离

- 玩家安全包不得包含完整 GM 工作档案；本项目完整工作档案属于主持端内部资料。
- 不得把隐藏真相写进玩家安全启动文本，再指望模型“不要看”或“不要剧透”。一旦机密被复制到玩家可见上下文，不能把它视为真正隔离。
- 如果新聊天无法安全取得主持端机密，必须诚实说明：它只能按玩家安全资料运行，不能声称已载入未提供的秘密文件。不得为补齐“记忆”而在玩家安全包中泄露秘密。
- 如果确实需要另一个主持端恢复全部隐藏真相，必须在受控的主持端流程中单独提供机密包；不能把同一个对话同时当作可靠的秘密存储和玩家可见叙事窗口。

## 6. 文件校验与恢复

每次发布记录：
- 交接 ID（唯一且不可复用）
- 游戏版本与存档版本
- 玩家安全包文件清单和每个文件 SHA-256
- 压缩包 SHA-256 与压缩完整性测试结果
- 机密包独立清单（仅主持端保存）
- 最后一个已确认场景编号、游戏内时间和存档版本
- 未解决的连续性问题

哈希值只能证明文件字节是否变化，不能证明设定本身一定正确；语义一致性仍需清单核对和实际接手测试。文件名、版本号、哈希值任一不匹配，都要暂停使用并查明原因。

## 7. 交接对抗测试

- **测试 A：安全包泄漏扫描**——包内不得出现任何完整 GM 文件或隐藏附页。
- **测试 B：缺文件测试**——故意缺少一个公开文件，新聊天应报告缺失，不可假称读过。
- **测试 C：状态矛盾测试**——余额/伤势/地点冲突时应暂停相关结算并列出冲突。
- **测试 D：猜测测试**——玩家猜中秘密不改变真相；依据角色证据判定角色是否真正确认。
- **测试 E：版本回退测试**——旧存档不能覆盖更新的已确认状态，除非用户明确恢复旧版。
- **测试 F：临时内容隔离**——模拟角色、测试价格与候选地点不能进入正式正史。
- **测试 G：隐藏附页扫描**——公开存档不得包含主持端隐藏附页。

## 8. 绝对保证的边界

不能诚实承诺任何语言模型跨聊天“万无一失”或自动保留所有秘密。能做的是：严格分包、清单化、哈希校验、交接前后核对、发现矛盾就暂停、不声称读过未收到的文件，并在正式开始前做一次实际交接演练。若没有独立机密资料的安全存放与加载机制，玩家安全聊天不能同时作为隐藏真相的可靠秘密保险箱。

## 9. 正式交接的放行条件

只有全部满足才放行：
- [ ] 玩家安全包和主持端机密包物理分离。
- [ ] 玩家安全包无 GM-only 文件、隐藏附页和隐藏答案。
- [ ] 所有公开文件版本和校验清单一致。
- [ ] 存档账目、状态、时间和信息层级通过复核。
- [ ] 新聊天确认收到的文件清单，不虚报读取能力。
- [ ] 已完成至少一次模拟接手，缺失与矛盾能被正确识别。
- [ ] 用户知道“校验降低错误风险，但不是数学意义上的绝对保证”。
