# 《修仙》存档分离与新聊天交接测试 v0.1

> 主持端执行文件。目标：新聊天能够恢复游戏状态，但绝不能从玩家可见资料中直接读到未发现的幕后真相。

## 1. 三层文件边界

### A. 玩家可见层
- 玩家手册公开规则。
- 当前角色存档：只记录角色已知事实、亲历事件、已获得物品、已知关系、传闻、线索与角色自己的推断。
- 剧情回顾：只回顾角色经历过或合理获知的内容；明确区分事实、传闻与推断。
- 不得出现隐藏答案、NPC未公开真实动机、秘密事件状态机、未触发结局条件或玩家角色不可能知道的幕后时间线。

### B. 主持端机密层
- 隐藏历史与真实因果。
- NPC实际动机、实际知识边界、未公开计划。
- 尚未向角色暴露的事件状态、触发条件、线索安排与结局条件。
- 主持端连续性检查、未公开风险与秘密索引。

### C. 体验偏好层
- 用户确认的非剧情体验设置。
- 只影响规则细度、叙事呈现、判定习惯和风险说明，不携带隐藏剧情答案。
- 本项目当前默认：标准硬核、混合式战斗、因果优先、标准风险、均衡叙事。

## 2. 交接文件最小集合

新聊天准备正式开局时，优先提供：
1. 玩家安全启动文本。
2. 玩家手册（公开版）。
3. 最新玩家可见存档（首次开局则为空白模板或角色创建记录）。
4. 玩家可见剧情回顾/变更摘要（首次开局可为空）。
5. 体验偏好摘要（只含已确认的默认值）。

主持端机密文件只应在明确具备相应文件隔离条件的主持端工作流程中使用；不能把主持端圣经直接粘贴进玩家可见聊天或交接摘要。

## 3. 交接前检查清单

- [ ] 版本号与最后更新时间一致。
- [ ] 角色境界、伤势、疲劳、灵力、功法掌握阶段与实际叙述一致。
- [ ] 现金余额等于初始资金 + 收入 - 支出；物品数量逐项核对。
- [ ] 日期、时段、地点、已耗时间和仍有效期限一致。
- [ ] NPC关系分别记录信任、好感、利益、恐惧、承诺，不用单一“好感值”代替全部。
- [ ] 事实、传闻、线索、推断分栏，不把猜测写成事实。
- [ ] 未公开的 NPC 知识、幕后事件与真实答案没有混入玩家可见存档。
- [ ] 用户确认的体验偏好已同步；没有再次把已确认项目列为待选择。
- [ ] 临时模拟内容没有被误写为正式正史。
- [ ] 发现错误时透明修正，不以“隐藏剧情”掩盖主持端错误。

## 4. 对抗测试

### 测试 A：玩家只上传公开存档
预期：新主持端能恢复角色的公开状态与下一步可行动方向，但无法据此还原未公开的真实幕后答案。

### 测试 B：玩家在聊天中猜中隐藏真相
预期：不因猜测本身改变真相；按角色已有证据判断其是否真正确认。不得因为玩家猜中就强行否认合理证据，也不得凭空给予完整答案。

### 测试 C：主持端机密与玩家存档冲突
预期：暂停扩写，核对版本与事件记录。若是主持端记录错误，按变更流程透明修正；若是角色推断错误，保留角色的推断并注明证据不足。

### 测试 D：用户改变玩法偏好
预期：更新偏好层与生效节点，不改写隐藏历史或既有事件因果。

### 测试 E：临时角色与正式角色混淆
预期：任何带有“测试用/临时”标记的角色、地点、价格与事件不得自动进入正式正史。

## 5. 已知限制与正式开局门槛

- 文件隔离是流程要求，不应假装同一个玩家可见聊天能够安全隐藏已直接粘贴进去的机密内容。
- 新聊天若没有获得主持端机密资料，不能声称自己已读到所有隐藏设定；应使用玩家安全启动包，并按预先设计的公开行动规则继续，或在可用的受控主持端环境中加载机密资料。
- 公开存档不应为了“让新主持人懂剧情”而塞入玩家尚未发现的解释。
- 正式开局前仍需完成正式角色生成、地区/日历确定、货币与食物记录口径确认，以及公开/机密文件发布路径检查。

## 6. 本轮结论

存档格式可以记录角色状态，但真正的秘密隔离不只是模板问题，也取决于文件如何提供给新聊天。最安全的原则是：玩家可见包只包含公开规则和角色已知状态；机密资料不复制进玩家可见文本。此文件是流程测试标准，不宣称已验证任何平台具备自动隐藏附件的能力。
